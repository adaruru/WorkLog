- Wait Decision
  - 你不應該在對話中處理待確認事項，需要確認的東西應該要寫在 Wait Decision
  - 已經確認的內容不應該更新 Wait Decision
  - 已經確認的內容，跟規格相關，應該更新在 Spec
  - 已經確認的內容，跟工作相關，應該更新在 Goal
  - 已經確認的內容，是重要背景知識（使用者不懂、經過調查後得到），應更新在 Survey 現況調查

- Goal（使用者掌管，agent 唯讀）

  - task 表就是唯一的即時進度追蹤器：每一項開始做／做完就直接去動那個 checkbox，一項一項按順序走
  - task 不再另開一份內部 TaskList 自己追、然後事後回頭對帳核對
  - task 只勾實際做完的，沒做的維持 [ ]
  - task 只留勾選清單、說明全部移到 Survey、保持簡潔
- Survey
  - 使用者表示不懂、透過對話回答、上網搜尋的資訊，更新在 Survey
  - 使用者不確定、經調查詢程式碼、規格書查得到的背景知識、資訊

## Spec

### PMSpec

本 task 無 PM 規格書，需求來源為使用者口述，原文重點如下：

- 桌面小工具，資料庫使用內嵌 SQLite，不需要登入。
- 可建立使用者、可新增刪除使用者；每個使用者都有自己的工時輸入與規劃。
- 紀錄欄位：標題、內容、工單、關聯工單（陣列可輸多個）；選擇關聯工單時，最近有更新的最先出現。
- 工作狀態 active／closed／pending，且可自由新增減少其他狀態。
- 查詢：標題／內容／工單用一個欄位模糊搜尋；日期選擇查詢區間起訖；工作狀態可多過濾。
- 越輕量越好，Windows 可安裝，最好不要安裝可以直接執行。
- 介面漂亮一點、精簡小巧、設定面獨立；查詢介面與編輯介面要一起。
- 版面：上方搜尋欄位；左方過濾過的查詢結果列表，列表可直接下拉改狀態、編輯所有內容；右方點個別列表後出現內容、關聯工作。
- 點關聯工作，左方列表導航過去，右方顯示內容、關聯工作。
- 切換使用者視作搜尋條件一部分，不選使用者就搜尋全部。
- 要工時提醒：可設定使用者對應每日必填小時數，小工具要能說還差多少工時未輸入。

### UiSpec

#### 主畫面

| 區塊 | 內容 |
|---|---|
| 上方搜尋列 | 關鍵字輸入框、日期快捷下拉、日期起訖、狀態複選、使用者下拉、工時缺口徽章、設定入口 |
| 列表末端 | 置中的方框新增按鈕，唯一的新增入口，連按幾下就新增幾筆 |
| 左方列表 | 過濾後的紀錄列。未選中時緊湊顯示；選中的那一列就地展開成編輯區，工單、標題、日期、時數、狀態、使用者全部可改 |
| 右方詳情 | 選中紀錄的內容欄，下方為關聯工作區，列出同群組的其他紀錄 |

#### 搜尋列欄位

| 欄位 | 型別 | 預設 | 行為 |
|---|---|---|---|
| 關鍵字 | 文字 | 空 | 空值不過濾；有值時對 `title`／`content`／`ticket` 做模糊比對 |
| 日期快捷 | 單選 | 本週 | 今日／本週／本月／本 sprint／上個 sprint／自訂；選定後回填日期起訖 |
| 日期起 | 日期 | 依快捷 | 空值不設下界；手動改值時快捷切為自訂 |
| 日期訖 | 日期 | 依快捷 | 空值不設上界；手動改值時快捷切為自訂 |
| 狀態 | 複選 | 全不選 | 全不選等同不過濾 |
| 使用者 | 單選 | 未選 | 未選等同搜尋全部使用者；另有無擁有者選項可篩無主紀錄 |

| 已填多於應填 | 本週 超出 3 小時 |
| 未選使用者 | 未選取使用者 |

範圍文字跟隨 `reminder_range`，例如 `sprint 13 尚缺 22 小時`。

### 免安裝單檔與體積的取捨

選型定案為 Tauri 2。下表為當初的候選比較，留作日後回頭檢視選型理由的依據。

| 方案 | 單檔體積 | 免安裝條件 | 介面做漂亮的難度 | 維護成本 |
|---|---|---|---|---|
| Tauri 2（Rust + WebView2） | 約 5–10 MB | Windows 11 內建 WebView2 Runtime，無額外安裝 | 低，介面是 HTML/CSS，任何現成設計都能套 | 高，需要 Rust 工具鏈與 Rust 語言 |
| Avalonia（.NET self-contained single-file） | 約 35–70 MB，trim 後約 30 MB | 產物自帶 runtime，直接執行 | 中，Fluent 主題堪用，細緻視覺要自刻 control template | 低，使用者既有 C# 技術棧 |
| Photino.NET（.NET + WebView2） | 約 35–70 MB | 同上，另需 WebView2 Runtime | 低，介面同為 HTML/CSS | 低，C# 後端搭前端頁面 |

- Electron 排除：產物 150 MB 起跳，與「越輕量越好」直接衝突。
- 「Windows 可安裝」與「最好不要安裝可以直接執行」以後者為準，三個方案都輸出單一 exe。
- Tauri 的 Rust 端在本工具只負責 SQLite 存取與少量計算，語言學習面積有限。

### SQLite 的中文模糊搜尋

- FTS5 的預設 tokenizer 以空白與標點斷詞，中文整句會被當成單一 token，搜「工時」搜不到「工時輸入」。要用 FTS5 必須指定 `tokenize='trigram'`（SQLite 3.34 以後支援）。
- 本工具為單機、單人、資料量在數千筆量級，`LIKE '%關鍵字%'` 的全表掃描在這個量級下感受不到延遲，且無需維護 FTS 索引表與觸發器。
- 結論：關鍵字查詢用 `LIKE`，不導入 FTS5。

### 關聯工作的語意

- 需求同時出現「工單」與「關聯工單」兩個欄位，且「點關聯工作，左方列表導航過去」代表關聯的目標是本工具內既有的紀錄。
- 因此 `entries.ticket` 是自由文字的外部工單編號，`entry_links` 存的是本工具內 `entries.id` 的參照，兩者語意不同。

### WebView2 會吃掉瀏覽器快捷鍵

- WebView2 的核心是 Chromium，預設把 F1、F3、F5、F7、Ctrl+F、Ctrl+P 這些視為自己的快捷鍵。視窗有焦點時，這些鍵在到達其他程式之前就被消費掉，使用者的截圖工具之類的全域熱鍵會失效。
- 關閉方式是 WebView2 的 `AreBrowserAcceleratorKeysEnabled` 設為 false。Tauri 沒有把這個開關接出來（wry 有 `with_browser_accelerator_keys`，未往上暴露），所以改用 `WebviewWindow::with_webview` 取得 `ICoreWebView2Controller`，在視窗建立後自行設定。
- 需要的 `webview2-com` 與 `windows` 兩個相依，版本對齊 `Cargo.lock` 裡 wry 已在使用的 0.38 與 0.61，不會多拉新套件，產物體積不變。

### Sprint 編號的推算

- 設定面只登記一個基準點：某個 sprint 的編號、該 sprint 的起始日、每個 sprint 的天數。例如登記 sprint 12 起於 `2026-09-01`、每個 sprint 14 天。
- 有了基準點，任何 sprint 的起訖日與任何日期所屬的 sprint 編號都能算出來，不必逐個 sprint 手動維護。

## Design 設計

### 資料庫

1. 單一 SQLite 檔，預設落在 exe 同目錄，啟動時若不存在就建檔並跑初始化腳本。
2. 初始化寫入 new／active／pending／closed 四筆 `is_builtin = 1` 的狀態，`default_status_id` 指向 new。
3. `app_settings` 存 schema 版本，啟動時比對並執行升級腳本。

> 設計決策（已定案）：資料庫檔放 exe 同目錄。理由：整個資料夾可以丟隨身碟帶走，符合免安裝的使用方式。代價是 exe 放在 `Program Files` 這類目錄時會因權限寫不進去，設定面因此提供路徑切換。

> 設計決策（已定案）：`hours` 存 REAL 而非分鐘整數。理由：輸入介面以小時為單位（0.5、1.5），存 REAL 免去進出雙向換算；缺口計算為加總比較，REAL 的精度誤差在單日 24 小時量級下不影響顯示到小數一位的結果。

### 查詢

1. 關鍵字：`title LIKE @k OR content LIKE @k OR ticket LIKE @k`，`@k` 兩側補 `%`。
2. 日期區間：`work_date >= @from AND work_date <= @to`，任一端為空就不加該條件。`work_date` 存 `yyyy-MM-dd` 字串，字典序等同日期序，直接比字串。
3. 狀態複選：`status_id IN (...)`，全不選就不加條件。
4. 使用者：`user_id = @userId`，未選就不加條件；選無擁有者時改為 `user_id IS NULL`。
5. 四個條件以 AND 串接，未提供的條件不進 SQL。
6. 列表排序為 `work_date` 由新到舊、同日再依 `updated_at` 由新到舊。

### 關聯工作

1. 關聯是**群組**，沒有方向。把「登入頁改版」加到「修登入頁 bug」的關聯後，兩筆同屬一個群組，彼此互為關聯。
2. 群組會合併：群組內任一筆再關聯到另一個群組的任一筆，兩個群組併成一個。
3. 詳情頁的關聯區列出同群組的其他成員，排序 `updated_at` 由新到舊。
4. 移除只把該筆移出群組，群組其餘成員之間的關聯不受影響；群組剩下一名成員時自動解散。
5. 挑選清單的來源為全部紀錄，排序 `updated_at DESC`，排除自己與同群組成員，並吃關鍵字過濾。

> 設計決策（已定案）：用 `entries.group_id` 表示群組，取代原本的 `entry_links` 有向邊。理由：需求是「誰關聯誰都無所謂」，有向邊得在讀取時算連通分量、在刪除時處理間接相連的孤兒；群組欄位讓「同群組」變成一次相等比較，加入是合併、移除是清空，沒有方向可言。

### 日期快捷與 sprint

1. 快捷下拉與日期起訖雙向連動：選快捷即算出起訖並回填輸入框；手動改動任一端日期，快捷切為自訂。
2. 本週定義為週一至週日。
3. sprint 起訖由基準點推算：第 n 個 sprint 的起日為 `anchor_start + (n − anchor_number) × sprint_length_days`，訖日為起日加 `sprint_length_days − 1` 天。
4. 今日所屬 sprint 編號為 `anchor_number + floor((今日 − anchor_start) ÷ sprint_length_days)`。
5. sprint 基準尚未設定時，本 sprint 與上個 sprint 兩個快捷停用，並在設定面提示前往登記。

### 刪除的連動

1. 刪除使用者：該使用者的紀錄保留，`entries.user_id` 改為 NULL 成為無主紀錄；同時刪除該使用者的請假資料。
2. 無主紀錄查得到、編輯得了，但不參與工時缺口計算，因為缺口以每位使用者的每日必填時數為基準。
3. 刪除狀態：跳出替代狀態選單，預設帶 `default_status_id`，確認後把引用該狀態的紀錄改掛選定狀態。
4. `default_status_id` 指向的狀態不可刪除，避免替代目標落空。

### 工時缺口

1. 缺口的計算範圍取 `reminder_range`，與搜尋列的日期區間各自獨立：搜尋列決定看哪些紀錄，`reminder_range` 決定提醒盯哪段期間。
2. 應填時數 `required(d)`：週六、週日與 `holidays` 內的日期為零；其餘日期為該使用者的 `daily_required_hours` 減去當日請假時數，減完低於零時取零。
3. 已填時數 `filled(d)`：該使用者當日全部紀錄的 `hours` 加總，不分狀態。
4. 區間結果為 `Σ filled − Σ required`：小於零顯示尚缺、等於零顯示剛好達標、大於零顯示超出。
5. 未選使用者時，缺口徽章顯示未選取使用者，不做跨使用者加總。

> 設計決策（已定案）：全部狀態的 `hours` 都計入已填時數。理由：缺口要回答的是工時有沒有填滿，與該筆工作進行到哪個階段無關。

### 提醒

1. 主畫面搜尋列常駐缺口徽章。
2. 系統匣常駐圖示，關閉視窗後程式續留背景，圖示的 tooltip 顯示與徽章相同的缺口文字。
3. `reminder_range` 可在設定面切換今日、本週、本 sprint，徽章與系統匣同步套用。

### 視覺設計

設計語言走高密度工具風，深、淺、藍三套主題共用同一組尺寸與互動規則，只換配色變數。

| 項目 | 規格 |
|---|---|
| 字級 | 主要 12.5px、標題 13px、次要資訊 11px |
| 字體 | `Segoe UI Variable`、`Inter`、系統 sans-serif；數字欄位加 `font-variant-numeric: tabular-nums` |
| 圓角 | 控制項與卡片 6px，色點與徽章用全圓角 |
| 控制項高度 | 輸入框與下拉 26px，按鈕 26px |
| 列表列高 | 30px，兩行式列則 44px |
| 邊框 | 1px，顏色取自主題的 border 變數 |
| 陰影 | 僅浮層（下拉選單、關聯挑選）使用，其餘不加 |
| 過渡 | 背景與邊框 120ms ease，只作用在 hover 與 focus |

每套主題定義同一組變數：`--bg-canvas`（最底層）、`--bg-surface`（列表與詳情面板）、`--bg-elevated`（浮層與 hover）、`--border`、`--text`、`--text-dim`、`--accent`。三層背景是高密度版面不靠留白也分得清區塊的關鍵。

- 選中列：左側 2px 強調色直條加 `--bg-elevated` 底色，不改字重，避免列高跳動。
- 狀態呈現：7px 圓點加名稱，圓點取 `statuses.color`，讓列表掃視時靠顏色定位。
- 缺口徽章：不足為琥珀、剛好達標為綠、超出為藍，底色為該色 12% 透明度，文字為該色本身。
- 焦點環：2px 強調色 30% 透明外擴，鍵盤操作看得見，滑鼠點擊不顯示。
- 圖示：inline SVG、16px、stroke 1.5，不引入圖示字型檔。
- 空狀態：置中的單行說明文字加一個淡色圖示，不做插畫。

### 介面導航

1. 左方列表與右方詳情共用同一個選中 id，點列表列或點關聯工作都是改這個 id。
2. 點關聯工作時，若目標紀錄不在目前的過濾結果內，清掉關鍵字與狀態過濾後重新查詢再選中，並提示過濾條件已放寬。
3. 左方列表的狀態下拉改完立即寫庫並更新 `updated_at`，不需按儲存。
4. 編輯就地發生在左方列表：選中的那一列展開成編輯區，其餘列維持單行緊湊顯示。
5. 右方只放內容欄與關聯工作，不重複列表已有的欄位。
6. 切換選中列時若當前列有未儲存的改動，先自動存檔再切換，不跳提示。
5. 使用者清單一律依建立時間由舊到新排列，下拉選單與新紀錄的預設值都吃這個順序。
6. 新紀錄的使用者預設值：搜尋列已選某位使用者就沿用，選了無擁有者就留空，沒選使用者則帶入最早建立的那位。
